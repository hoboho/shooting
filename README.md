# شوتینگ (Shooting)

برنامه ای **مستقل، کاملاً آفلاین و فارسیزبان** برای ثبت، مدیریت و گزارشدهی عملیات
شوتینگ (کابلکشی فیبر نوری) روی اندروید. این مخزن یک اپلیکیشن مستقل است و هیچ
وابستگی به پروژهٔ Metra یا کتابخانه/ماژول/بکند آن ندارد؛ Metra فقط **مرجع طراحی
بصری و تجربهٔ کاربری** بوده است (رنگها، تایپوگرافی Vazirmatn، چیدمان RTL،
کامپوننتها، تقویم جلالی، قالببندی اعداد و سبک گزارش PDF).

- نام بسته: `ir.hoboho.shooting` · مخزن: `hoboho/shooting`
- زبان رابط: فارسی (`localeFilters=fa`) · تاریخ: هجری شمسی · پول: **تومانِ عدد صحیح**
- بدون حساب کاربری، بدون احراز هویت، بدون سرور/فضای ابری، بدون آنالیتیکس، بدون
 مجوز `INTERNET`. پایگاه دادهٔ Room روی خود دستگاه تن ها منبع حقیقت است.

## دانلود آخرین ساخت

لینک های زیر پایدار اند و با هر ساخت تازهٔ CI بهروز می شوند. این فایل ها
**ساخت دیباگ** اند، نه نسخهٔ امضا شدهٔ انتشار:

| فایل | لینک مستقیم |
| --- | --- |
| APK دیباگ | [Shooting-debug.apk](https://github.com/hoboho/shooting/releases/download/debug-latest/Shooting-debug.apk) |
| بستهٔ کامل ZIP (APK، گزارش های آزمون/لینت، اسکیمای Room، نمونه های PDF) | [Shooting-latest.zip](https://github.com/hoboho/shooting/releases/download/debug-latest/Shooting-latest.zip) |

برگهٔ [پیش انتشار debug-latest](https://github.com/hoboho/shooting/releases/tag/debug-latest)
و [اجرا های GitHub Actions](https://github.com/hoboho/shooting/actions) نیز در دسترس اند.
انتشار این دو فایل با کامیت حاوی `[publish-apk]` یا اجرای دستی گردشکار انجام
می شود؛ داخل فایل ZIP، پروندهٔ `BUILD-INFO.txt` کامیت و اجرای مربوطه را مشخص
می کند.

| تسویه ها | چند تسویه برای هر هزینه؛ «تسویه نشده / جزئی / کامل»؛ `مانده = مبلغ هزینه − جمع تسویه ها`؛ جلوگیری از ثبت تسویه بیش از مانده |
| گزارش ها | گزارش روزانه، گزارشدوره ای (بازه تاریخ + فیلتر پروژه)، گزارش هزینه ها و تسویهها؛ تفکیک نوع کابل در UI و PDF؛ طول ها و مبالغ **هرگز** با هم جمع یا ترکیب نمی شوند |
| خروجی PDF | A4 فارسی RTL، فونت Vazirmatn، ارقام فارسی، تاریخ جلالی، تومان، سرستون های تکرارشونده، شماره صفحه؛ سه نوع گزارش + تفکیک نوع کابل؛ ذخیره خودکار در Downloads/Shooting علاوه بر ارسال |
| پشتیبان گیری | قالب نسخهدار + بررسی یکپارچگی SHA-256، پیش نمایش، سه راهبرد صریح بازیابی، نسخهٔ ایمنی پیش از هر بازیابی، بدون جایگزینی خاموش؛ فایل پشتیبان نیز روی دستگاه ذخیره می شود |

داده های مرجع (کور های استاندارد `۲/۴/۶/۱۲/۲۴/۳۶/۴۸/۷۲/۹۶/۱۴۴/۲۸۸` و هفت دستهٔ هزینه)
ردیف های معمولی پایگاه داده اند؛ افزودن/غیر فعال کردن آن ها نیازی به تغییر اسکیما
ندارد. این فهرست بر اساس مقادیر رایج تجاری و استاندارد TIA انتخاب شده است
([استاندارد TIA](https://www.csemag.com/articles/fiber-optics-a-backbone-for-advanced-building-design/),
[راهنمای تعداد کور](https://www.cobtel.com/info/how-many-core-in-fiber-optic-cable-the-comple-103687610.html)).

## معماری در یک نگاه

```
app/src/main/java/ir/hoboho/shooting/
├── core/       تاریخ جلالی، قالببندی، مدل/موتور PDF، JSON/نگاشت/مدیریت پشتیبان، اشتراکگذاری
├── domain/     مدلها، اعتبارسنجی، محاسبات، تجمیع دورهای، ساخت مشخصات گزارش
├── data/       موجودیتها/DAOهای Room، نگاشتها، پیادهسازی مخازن
├── di/         ماژولهای Hilt، مهاجرتها، Seed اولیه
├── ui/         تم Material 3 همسان با Metra، کامپوننتها، ناوبری
└── feature/    داشبورد، پروژهها، گزارشهای روزانه، هزینهها، گزارشها، تنظیمات/پشتیبان
```

جریان اصلی: **پروژه → گزارش روزانه → افزودن عملیات (طول خودکار) → ذخیره →
ثبت هزینه/تسویه → مشاهده گزارش ها و مانده مطالبات.**

جزئیات بیشتر: [معماری](docs/ARCHITECTURE.md) · [مدل داده](docs/DATA_MODEL.md) ·
[ساخت](docs/BUILD.md) · [آزمون ها](docs/TESTING.md) ·
[پشتیبان گیری و PDF](docs/BACKUP_AND_PDF.md) · [وضعیت کنترل کیفیت](docs/QA.md).

## ساخت و اجرا

نیازمندی ها: **JDK 21**، Android SDK (platform 37، buildtools)، Gradle 9.6.0 از
طریق wrapper موجود. هیچ کلید/توکن/سرویس ابری لازم نیست.

```bash
git clone https://github.com/hoboho/shooting.git
cd shooting
./gradlew :app:assembleDebug          # APK: app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:testDebugUnitTest      # ۶۲ آزمون JVM
./gradlew :app:lintDebug              # تحلیل ایستا
./gradlew :app:connectedDebugAndroidTest  # آزمونهای Room و جریانهای کاری روی دستگاه/امولاتور
```

`README` و مستندات دقیقتر در [docs/BUILD.md](docs/BUILD.md) و
[docs/TESTING.md](docs/TESTING.md). گردشکار GitHub Actions در
[`.github/workflows/android.yml`](.github/workflows/android.yml) همان دستورات را
اجرا می کند و APK، گزارش آزمون/لینت و اسکیمای Room را بهعنوان artifact بارگذاری
می کند و سه نمونهٔ PDF تولیدشده در آزمون جریان کاری را نیز با artifact
`qa-pdf-samples` بارگذاری مینماید. اجرا های
[PR 41480196402](https://github.com/hoboho/shooting/actions/runs/41480196402) و
[push 41480188364](https://github.com/hoboho/shooting/actions/runs/41480188364)
بهعنوان اجرا های مرجع تأیید ساخت، هر سه job را با `success` به پایان رساندند؛ جزئیات پایدار
در [وضعیت کنترل کیفیت](docs/QA.md) قابل مشاهده است.

### اجرا بدون Gradle (محیط آفلاین)

دو ابزار کمکی وجود دارند که بدون Android SDK اجرا می شوند:

```bash
python3 scripts/check_sources.py                 # بررسی منابع، importها، ناوبری، قواعد حیاتی
KOTLINC=/path/to/kotlinc bash scripts/run-offline-tests.sh  # آزمونهای خالص Kotlin
KOTLINC=/path/to/kotlinc COROUTINES_JAR=/path/to/kotlinx-coroutines-core-jvm.jar \
  bash scripts/offline-compile-check/run.sh   # کامپایل ۴۲ فایل core/domain/data/di با استاب
```

دومی همان ۱۳ فایل آزمون `app/src/test` را با یک اجراکنندهٔ بازتابی کوچک اجرا
می کند؛ در Gradle این آزمون ها بدون تغییر با JUnit واقعی اجرا می شوند. **این ابزار ها
جایگزین کامپایل اندروید، لینت یا ساخت APK نیستند.**

## وضعیت تأیید (مهم)

> **توجه:** جدول و اجرا های زیر وضعیت کامیت پیش از تغییرات اخیر (کیبورد عددی،
> ذخیرهٔ خودکار PDF/پشتیبان، کور های استاندارد، تفکیک نوع کابل و اصلاح نگارشی)
> را ثبت می کنند؛ اجرا های تازهٔ این شاخه در برگهٔ Actions مخزن قابل بررسی اند.

اجرا های مرجع تأییدشدهٔ [PR 41480196402](https://github.com/hoboho/shooting/actions/runs/41480196402)
و [push 41480188364](https://github.com/hoboho/shooting/actions/runs/41480188364)
با نتیجهٔ `success` برای هر سه job به پایان رسیدند. اجرای
قدیمی [41394294285](https://github.com/hoboho/shooting/actions/runs/41394294285)
همچنان مرجع نخستین ساخت کامل است؛ کامیت های بعدی همان گردشکار را روی push/PR
اجرا می کنند.

| مورد | وضعیت |
| --- | --- |
| آزمون های منطق خالص JVM | ✅ اجرا و عبور: **۶۲ از ۶۲** (harness آفلاین)؛ `testDebugUnitTest` نیز در CI عبور کرد |
| بررسی های ایستای `check_sources.py` | ✅ اجرا و عبور: ۰ خطا (محلی و job نخست CI) |
| کامپایل ۴۲ فایل `core/domain/data/di` با `kotlinc` واقعی + استاب API | ✅ اجرا و عبور: `exit 0` (کمکی، نه کامپایل اندروید) |
| کامپایل منابع اندروید/Compose/Room/Hilt/KSP، `lintDebug`، `assembleDebug` و خروجی اسکیمای Room | ✅ اجرا و عبور در job دوم CI؛ APK و گزارش ها بهعنوان artifact بارگذاری شدند |
| آزمون های instrumentation Room/اسکیما و جریان های کاری روی امولاتور API 34 | ✅ **۱۲ آزمون** در job سوم CI: `tests="12" failures="0" errors="0" skipped="0"`؛ شامل رندر خودکار هر سه PDF و artifact نمونه ها |
| اسکیمای نسخهٔ ۱ و سیاست مهاجرت | ✅ شکل v1 روی SQLite واقعی بررسی و JSON توسط KSP تولید/بارگذاری شد؛ نسخهٔ فعلی v1 است و مهاجرتی وجود ندارد |
| بازبینی بصری صفحات و PDF، اجرای دستی جریان روزانه/هزینه/تسویه/پشتیبان، حالت تاریک و چرخش | ⏳ انجام نشده؛ چکلیست دقیق در [QA](docs/QA.md) |

در محیط توسعهٔ محلی همچنان `./gradlew` بهدلیل نبود Android SDK و عدم دسترسی به
مخازن Gradle قابل اجرا نیست؛ اجرا های اندرویدی فوق روی runner دارای SDK انجام
شدهاند. این موفقیت فقط **ساخت و آزمون های خودکار** را اثبات می کند و بهمعنای
تأیید کیفیت بصری، جریان های دستی یا «آمادهٔ انتشار» بودن اپلیکیشن نیست.
