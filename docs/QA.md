# وضعیت کنترل کیفیت

نتیجهٔ موفق فقط به همان کامیت و محیط اجرای آزمون مربوط است؛ وجود آزمون یا موفقیت یک اجرای قدیمی، تأیید شاخهٔ فعلی و آمادگی انتشار نیست. دستورات و پوشش فعلی در [TESTING.md](TESTING.md) آمده‌اند.

## بررسی این بازبینی

- `python3 scripts/check_sources.py`: در بازبینی ۲۰۲۶-۱۱-۲۰، خروجی `0 error(s), 0 warning(s)` بود.
- آزمون‌های Gradle، ساخت APK، lint و instrumentation در آن بازبینی اجرا نشدند: Java و Android SDK در محیط موجود نبودند. وضعیت آن‌ها برای این شاخه را از اجرای مربوط به همان کامیت در Actions بررسی کنید.

## اجراهای تاریخی CI

در [PR run 41480196402](https://github.com/hoboho/shooting/actions/runs/41480196402) و [push run 41480188364](https://github.com/hoboho/shooting/actions/runs/41480188364)، بنا بر گزارش قبلی این سند، سه job بررسی ایستا، JVM/build و instrumentation موفق بوده‌اند و خروجی instrumentation دوازده آزمون بدون شکست را نشان داده است. این اجراها مربوط به نسخهٔ قدیمی‌تر کد هستند، نه شاخهٔ فعلی. artifactهای همان اجراها شامل گزارش آزمون، APK دیباگ، اسکیمای تولیدشده و نمونه‌های PDF بوده‌اند؛ در دسترس بودن آن‌ها به نگهداری artifact در GitHub بستگی دارد.

گردشکار کنونی در [android.yml](../.github/workflows/android.yml) تعریف شده است. نتیجهٔ هر job و artifactهای اجرای مربوط به کامیت موردنظر، مرجع وضعیت فعلی‌اند.

## موارد باز برای تأیید کیفیت

- [ ] اجرای آزمون‌های JVM، lint و ساخت دیباگ برای کامیت مورد بررسی.
- [ ] اجرای آزمون‌های instrumentation روی API 34 و بررسی گزارش شکست‌ها؛ وجود آزمون به‌تنهایی به‌معنای عبور آن نیست.
- [ ] بازیابی و ثبت اسکیماهای واقعی تاریخی Room و آزمودن مسیرهای ارتقا با `MigrationTestHelper`، از جمله داده‌های مالی در مهاجرت ۵ به ۶. نسخهٔ فعلی DB شش است؛ جزئیات و محدودیت آزمون‌های موجود در [راهنمای اسکیما](../app/schemas/README.md) آمده است.
- [ ] آزمون round-trip پشتیبان برای وضعیت تأیید هزینه، تسویه، دفتر نقدی و هر سه راهبرد بازیابی، از جمله بازیابی تکراری.
- [ ] نصب روی دستگاه و بررسی دستی صفحات و جریان روزانه، از جمله ثبت چند گزارش برای یک پروژه و تاریخ و ویرایش آن‌ها.
- [ ] بررسی دستی هزینه، تأیید شرکت، دریافتی، تسویه، مانده و گزارش‌های فیلترشده.
- [ ] بازبینی بصری PDFها از نظر RTL، حروف فارسی، ارقام و صفحه‌بندی.
- [ ] بررسی دستی ساخت و بازیابی پشتیبان، نسخهٔ ایمنی، حالت تاریک، چرخش صفحه و دسترس‌پذیری.

عبور آزمون‌های خودکار جایگزین بررسی انسانی نیست؛ تا انجام بررسی‌های مربوط به نسخهٔ مورد انتشار، آمادگی انتشار تأیید نشده است.
